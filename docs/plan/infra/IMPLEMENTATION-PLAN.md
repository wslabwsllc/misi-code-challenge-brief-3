## 1. Mission and scope

Configure and deploy the environment the application runs in:

1. Repository tooling and the one-command **local** stack (Dockerfiles, `compose.yml`, `tools/Dev`).
2. **Terraform** for AWS dev and prod: isolated network, RDS PostgreSQL, Secrets Manager, S3, ALB, ECS Fargate (web, worker, migrate, six mocks), identity for CI.
3. **GitHub Actions** workflows: PR validation, deploy, destroy.
4. Deployment evidence, runbook, cost control.

Out of scope: product behaviour, schema, pages, adapters, tests content (other boundaries). Also out: WAF, CloudFront, multi-region, real SFTP (Transfer Family). Production is in scope as a separately protected, opt-in environment using the same modules and parity checks as dev.

## 4. Target architecture

Same as master section 4.2 and 4.6 (unchanged by the CI switch). Compose → AWS mapping: `db` → RDS; `minio/storage` → S3 bucket; `migrate` → one-off task; `web` ×2 behind ALB; `worker` ×1; six `mock-*` → six ECS services; secrets by Terraform; logs to CloudWatch `/misi3/<environment>/<service>`. Dev and prod use the same modules with separate state, networking and protected deployment environments.

Layout you create:

```text
infra/{README.md, manual/README.md, bootstrap/, modules/{network,database,secrets,storage_s3,load_balancer,dns_certificate,ecs_app}/, envs/dev/, scripts/{run-one-off-task.sh,smoke-http.sh,smoke-https.sh,check-guards.sh}, .tflint.hcl}
.github/
  workflows/{pr-validation.yml, deploy.yml, destroy.yml, identity-check.yml (temporary), _build-test.yml, _images.yml, _terraform.yml}
  actions/{install-tool/, setup-dotnet/, aws-terraform/}        composite actions
  dependabot.yml
docs/aws/{GITHUB-ACTIONS-SETUP-GUIDE.md, AWS-OPERATIONS.md, CONFIGURATION-AWS.md}
docs/CONFIGURATION.md
```

`default_tags`: `Project=misi-event-permits`, `Environment`, `ManagedBy=terraform`, `Repository=misi-code-challenge-brief-3`, `Stack=<bootstrap|dev|prod>`. Names `misi3-<env>-<name>`.

The load-balancer module must expose parameterized inputs for `domain_name`/`base_domain`, `route53_zone_id`, `vpc_id`, `subnets`, backend target group and security-group IDs. With a non-empty domain it creates `aws_acm_certificate`, DNS validation records, `aws_acm_certificate_validation`, an HTTPS listener using `ELBSecurityPolicy-TLS13-1-2-2021-06`, and an HTTP listener that redirects with `#{protocol}`, `#{host}`, `#{path}` and `#{query}`. The HTTPS listener explicitly depends on certificate validation. With no domain, it creates only the HTTP listener and reports the ALB DNS URL.

## 6. Rewritten stories (GitHub Actions)

### 6.1 E14-02 Bootstrap: CI identity · M0 (write) / human apply

- AC1 `infra/bootstrap` reads the GitHub OIDC provider by data source if it exists. If the human finds none (E15-01 step 1), a variable `create_github_oidc_provider = true` creates `aws_iam_openid_connect_provider` for `https://token.actions.githubusercontent.com` with `client_id_list = ["sts.amazonaws.com"]`; check the pinned provider docs on whether `thumbprint_list` is still required. Bootstrap never destroys a provider it did not create; a provider it created is documented as shared and protected from `terraform destroy` of the dev stack (it lives only in the bootstrap state).
- AC2 Roles `misi3-gha-plan` and `misi3-gha-deploy` under path `/gha/`. Trust: `StringEquals` on `token.actions.githubusercontent.com:aud = sts.amazonaws.com` and on `:sub`:
  - plan: `repo:wslabwsllc/misi-code-challenge-brief-3:pull_request` and `repo:wslabwsllc/misi-code-challenge-brief-3:ref:refs/heads/main`;
  -   deploy: `repo:wslabwsllc/misi-code-challenge-brief-3:environment:aws-misi3-dev` or `repo:wslabwsllc/misi-code-challenge-brief-3:environment:aws-misi3-prod`, with the workflow selecting the matching protected environment.
  The `sub` is case-sensitive. Record the `sub` actually received on the first run (E15-01 AC2); GitHub allows custom subject templates, so confirm the default format is in force.
- AC3 Permissions as master E14-02 AC2 (plan: ReadOnly + state read for `dev/*` and `bootstrap/*` + lock files + `secretsmanager:GetSecretValue` on `misi3/*`; deploy: dev-stack services, ECR on the two repositories only, explicit denies on hand-made resources and on modifying `/gha/` roles). Policy sizes checked against IAM limits.
- AC4 Human applies it with state key `bootstrap/terraform.tfstate`; challenge-2 roles and provider unchanged (plan shows nothing outside the new resources); with the deploy role, `aws ecr delete-repository` is denied (recorded once).

### 6.2 E15-01 GitHub setup guide `[HUMAN + agent]` · M0

`docs/aws/GITHUB-ACTIONS-SETUP-GUIDE.md`, a checklist table plus click-by-click steps, only what a person must do:

1. Check whether the GitHub OIDC provider exists in AWS (`aws iam list-open-id-connect-providers`); choose `create_github_oidc_provider`.
2. Create the hand-made resources (E14-01) and return the verification output.
3. Apply bootstrap (E14-02); return outputs (role ARNs).
4. GitHub → Settings → **Environments** → create `aws-misi3-dev` and `aws-misi3-prod`: deployment branches = `main` only; required reviewer for prod (and recommended before destroy); no secrets.
5. Settings → Secrets and variables → Actions → **Variables**: `AWS_REGION`, `AWS_ACCOUNT_ID`, `TF_STATE_BUCKET`, `BASE_DOMAIN` (empty = HTTP), `DNS_MODE`; plus `AWS_PLAN_ROLE_ARN`, `AWS_DEPLOY_ROLE_ARN` (ARNs are not secret). No AWS secrets.
6. Settings → Actions → General: workflow permissions **read-only** by default; "Require approval for first-time contributors" (or all outside collaborators); allow only GitHub-owned actions plus the pinned list from `docs/DEPENDENCIES.md`; require full-SHA pinning if the setting is available.
7. Settings → Rules → **ruleset on `main`**: PR required, required status check `pr-validation / required`, block force pushes and deletion, linear history optional. Warn that from now on every boundary delivers through PRs.
8. Run `identity-check.yml` (manual): prints `aws sts get-caller-identity` per role showing the expected role; an attempt from a non-`main` branch with the deploy role must fail. Delete the workflow afterwards.
9. "Domain" section: no domain currently means ALB-DNS HTTP; a future domain gives `https://<environment>-brief3.<domain>` and documents which DNS records the human adds in `external` mode.
10. Troubleshooting table (e.g. `Not authorized to perform sts:AssumeRoleWithWebIdentity` → compare the printed `sub` claim with the trust policy).

Never ask the human to do anything not in this guide; add the step first.

### 6.3 E15-02 PR validation workflow · M0

`.github/workflows/pr-validation.yml`: `on: pull_request` (to `main`), `permissions: contents: read` at top, `concurrency: pr-validation-${{ github.ref }}` with `cancel-in-progress: true`. `runs-on: ubuntu-24.04`. Tools by checksum via `.github/actions/install-tool`. Jobs, parallel where independent:

| Job | Does |
| --- | --- |
| `dotnet` | `dotnet restore --locked-mode`, build with 0 warnings, unit + integration tests (Testcontainers), upload TRX (retention 14 days) |
| `browser` | `tools/Dev up`, full browser + axe suite, upload the HTML test report and failure screenshots; A-63 stays: CI evidence, not a Windows/Edge check |
| `images` | Build both images (`linux/amd64`), Trivy (fail on fixable CRITICAL) |
| `terraform` | fmt, validate, TFLint, Trivy config; **plan** with the plan role (`id-token: write` on this job only; skipped when the PR comes from a fork; no plan file uploaded) |
| `security` | Gitleaks on the diff, `check-guards.sh`, configuration-mapping check (E14-10), `actionlint` on `.github/**` |
| `required` | `needs` all of the above; this is the single required check in the ruleset |

AC: a PR with a failing test, a `terraform fmt` error or a fake secret fails the right job (record run URLs). Cache NuGet and Playwright browsers keyed by lock files.

### 6.4 E15-03 Deploy workflow · M0 (write) / first run at the M0 deploy

`.github/workflows/deploy.yml`: `on: workflow_dispatch` with optional input `imageTag` (redeploy/rollback); `concurrency: { group: misi3-deploy, cancel-in-progress: false }`; every job guarded by `if: github.ref == 'refs/heads/main'`.

1. `build-test` (no AWS): build, test, build both images tagged with the full commit SHA.
2. `plan` (plan role; log only; when `imageTag` is given, check both ECR repositories contain it).
3. `deploy` (`environment: aws-misi3-dev`, deploy role): push images (an existing immutable tag counts as success only if the digest matches), `terraform apply` (migrate runs first, I-10).
4. `verify`: select `smoke-https.sh <environment>-brief3.<base_domain>` when a domain exists (redirect, certificate for that exact host, TLS 1.2/1.3 only, headers, ALB DNS name → 404, `/webhooks/delivery` → 403), otherwise `smoke-http.sh <alb-dns-name>` (both also check that `/` returns the landing page anonymously); then `tools/Dev smoke --remote` and the `RemoteSmoke` browser subset (pinned .NET SDK from `global.json`, Playwright browsers matching the app package version). Seed credentials come from Secrets Manager into a mode-600 temp file deleted in an `if: always()` step; values are masked.

AC: rollback by `imageTag` proven once; run URL, commit SHA and UTC timestamps in STATUS.

### 6.5 E15-04 Destroy workflow and drill · M4

`.github/workflows/destroy.yml`: `workflow_dispatch` with inputs `confirmEnvironment` (must equal the selected `dev` or `prod` environment), `iUnderstandDataLoss` (must be `true`), `keepFinalSnapshot` (default `true`); runs in the matching protected GitHub environment so a required reviewer is a second confirmation; same concurrency group as deploy. Apply with protection off, then destroy; leftover check by tags, log groups (`/misi3/<environment>/`, Container Insights), Cloud Map namespace and `misi3/<environment>/*` secrets. Only hand-made resources and the optional final snapshot remain. The destroy → redeploy drill runs only with the user's go-ahead at that moment (or is recorded as *not executed*).

### 6.6 E15-06 Workflow hardening (new) · M0

- AC1 Every `uses:` is a full 40-character commit SHA with a version comment; list recorded in `docs/DEPENDENCIES.md`; `.github/dependabot.yml` for the `github-actions` ecosystem.
- AC2 `permissions: {}` or `contents: read` at workflow level; `id-token: write` only on jobs that call AWS; `persist-credentials: false` on checkout.
- AC3 No `pull_request_target`; no untrusted event data interpolated into `run:` (pass through `env:`); no secret echoed; plan files never uploaded.
- AC4 `actionlint` clean in PR validation (and optionally a GitHub-Actions security linter; verify the tool and version before adding).
- AC5 Billing note: private-repo Actions minutes are limited; record the measured PR run duration and caching choices in STATUS.

## 10. Definition of done for this boundary

1. All stories done, or *blocked* / *not executed* with reason and the exact command that would finish them.
2. `deploy.yml` from `main` deploys, migrates and seeds first, and verifies itself for dev and protected prod. HTTP mode serves `app_url`; HTTPS mode (if a domain is given) serves only `https://<environment>-brief3.<base_domain>` with a valid auto-renewing certificate.
3. No AWS access keys; no secret in Git, images, workflow logs, variables or STATUS.
4. Everything Terraform created is removed by `destroy.yml` in one run (drill passed or recorded as not executed); only hand-made resources and the optional snapshot survive.
5. Challenge-2 resources untouched (bootstrap plan evidence).
6. E14-12 acceptance table complete; STATUS separates passed, failed, not executed, blocked.

## 11. Risks

| Risk | Mitigation |
| --- | --- |
| App not ready when infra is | D0/D1 need no features; D2 needs only M0 |
| Contract gap found during deploy | Requests to the owning boundary; no workarounds in infra |
| Collision with challenge-2 resources | OD-4 naming; data sources only; review every plan for foreign changes |
